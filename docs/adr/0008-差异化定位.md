# ADR-0008 差异化定位：多品类商城 + 交易深度

- 状态：提议（待确认规则后转已接受）
- 日期：2026-10-28

## 背景

通用商城的功能清单高度同质：登录、商品、购物车、订单、后台、图表，再加一个聊天框。继续按 ISSUE-08 往下做，交付的会是一个"什么都有、什么都浅"的项目。

要在答辩与简历上拉开差距，靠的不是功能数量，而是**一个别人不愿做的深度**。选定两个方向：**售后与逆向物流闭环**（B）与**预售/定制交易**（C）；用垂直主题「独立设计 · 手作市集」把两者自然串起来——这个行业天然有工期、定金、做坏了、尺寸不对。

## 修订（2026-10-28）

初版把全站定位成"手作市集"，导致类目收窄为三个、首页文案偏向小众。修正为：

- **KDShop 首先是完整的购物网站**：8 个通用一级类目（食品饮料、家居日用、数码配件、服饰鞋包、美妆个护、图书文创、运动户外、母婴玩具）
- **家居 / 文具 / 礼物作为三个"特色专区"并存**（`categories.featured = 1`），不是全站身份
- 手作、限量、定制是**商品属性与交易能力**，任何类目都能用；首页保留专区入口，但主视觉是正常商城

差异化内核不变：定制交易（定金/尾款/工期）与售后闭环（质检/责任/超时裁决）。

## 定位

> KDShop 是一个面向独立设计师与手作工作室的多商家市集：支持**接单定制**（定金 + 尾款 + 工期承诺）与**完整售后**（仅退款 / 退货退款 / 质检入库 / 责任归属 / 超时自动裁决）。

三个支柱：

1. **定制交易**：商品分现货 / 预售 / 定制；定制商品收定金、按工期交付、超时自动赔付。
2. **售后闭环**：售后单独立建模，覆盖"申请 → 审核 → 寄回 → 质检 → 退款/拒绝"全链路，带超时自动裁决。
3. **账要算清**：售后期内冻结结算、退款冲抵、赔付从结算扣减，月末对账为零差异。

## 关键规则（默认值，待确认）

### 预售与定制

| 项 | 默认 | 说明 |
|---|---|---|
| 销售模式 | `IN_STOCK` / `PREORDER` / `CUSTOM` | 加在商品上，SKU 继承 |
| 定金比例 | 商品可配，默认 30% | 定金 = round(单价 × 比例)，最低 1 元 |
| 定金支付时限 | 24 小时 | 超时未付定金 → 订单取消 |
| 尾款通知 | 定金支付后 `lead_days - 3` 天 | 写入 outbox，站内信 + 邮件 |
| 尾款支付期限 | 通知后 7 天 | 逾期未付 → 订单关闭，**定金不退**（写入订单备注与售后规则） |
| 工期 | 商品配置 `lead_days`（3–60 天） | `promised_ship_at = 定金支付时间 + lead_days` |
| 超时赔付 | 每超 1 天赔定金 5%，上限 50% | 自动生成赔付记录，从商家结算扣减 |

### 售后

| 项 | 默认 | 说明 |
|---|---|---|
| 类型 | `REFUND_ONLY` 仅退款 / `RETURN_REFUND` 退货退款 | 换货列 V1.1，本期不做 |
| 可申请窗口 | 子单完成后 15 天内 | 定制商品仅支持"质量问题"与"与描述不符" |
| 商家审核时限 | 48 小时 | 超时自动通过（仅退款）/ 升级平台（退货退款） |
| 寄回时限 | 审核通过后 7 天 | 超时未寄回 → 售后关闭 |
| 质检 | 收货后 48 小时内 | 结果：良品（可二次销售）/ 残次（不可销售） |
| 责任归属 | 商家 / 物流 / 顾客 | 决定退货运费谁承担、是否计入商家责任率 |
| 库存回补 | 良品回补；残次不回补 | 与 ADR-0004 一致 |

### 与结算的关系

- 子单进入售后流程即**冻结结算**，直到售后关闭
- 已完成结算后发生退款的，从下一期结算冲抵（`refund_cent`）
- 赔付单与退款单都进结算明细，月末对账：`应结 = 已完成 - 退款 - 赔付`

## 不做什么

- 换货（V1.1）：需要再生成一条替换子单并复用发货，复杂度高、演示收益有限
- 跨境、税费、多仓：与差异化无关
- AI 客服：现在最同质化，且没有真实流量时指标无法自证

## 怎么证明

三个可演示场景，缺一不可：

1. **定制超时赔付**：下定金 → 商家逾期未发货 → 系统自动生成赔付 → 结算单里扣减
2. **退货质检**：收到货申请退货 → 商家同意 → 填寄回单号 → 商家质检判"残次" → 不入库、退款、责任计商家
3. **超时自动裁决**：商家 48 小时不处理 → 系统自动同意仅退款 → 订单状态与账目同步更新

## 何时重审

若答辩/验收更看重"功能广度"而非"交易深度"，本 ADR 需回退，改走通用路线。
