# M5 差异化：定制交易与售后闭环

目标：在通用商城之上，做出两条别人不会做的深度链路——**定金/尾款/工期的定制交易**，与**带质检和责任归属的售后闭环**。依据见 [ADR-0008](../adr/0008-差异化定位.md)。

前置：M2 的下单与支付（#11~#13）、M3 的商家子单（#20）已完成。

---

## ISSUE-33 销售模式与定金/工期配置

- 里程碑：M5 差异化
- 标签：`backend`, `merchant`, `catalog`
- 依赖：#19
- 需求：ADR-0008

**背景**：商品分现货、预售、定制；定制商品要配工期与定金比例。

**验收线**
- [ ] 商品增加销售模式，SKU 继承商品模式
- [ ] 定制/预售商品必须填 `lead_days`（3–60）与 `deposit_rate`，现货商品忽略这两项
- [ ] 前台商品卡片显示「预售 · 预计 N 天发货」「定金 30%」标识
- [ ] 数据库迁移 V3 可重复执行，种子数据补 3 个定制商品

**涉及**：`products`/`skus` 新增字段、`V3__preorder.sql`

## ISSUE-34 预售下单与定金支付

- 里程碑：M5 差异化
- 标签：`backend`, `order`, `payment`, `p0`
- 依赖：#11, #33
- 需求：ADR-0008

**背景**：定制商品下单只付定金，订单进入「制作中」。

**验收线**
- [ ] 定金 = round(单价 × 比例)，最低 1 元；订单记录 `deposit_cent` 与 `balance_cent`
- [ ] 定金支付成功 → 主单转「制作中」，子单记录 `promised_ship_at = 支付时间 + lead_days`
- [ ] 24 小时未付定金 → 自动取消并释放库存
- [ ] 一个主单可有多笔支付（定金 / 尾款），支付单增加 `purpose`

**涉及**：`POST /orders`、`POST /payments`、`payments` 表

## ISSUE-35 尾款支付与逾期规则

- 里程碑：M5 差异化
- 标签：`backend`, `order`, `payment`, `p1`
- 依赖：#34
- 需求：ADR-0008

**背景**：工期过半后通知付尾款，逾期视为违约。

**验收线**
- [ ] 尾款通知在 `promised_ship_at - 3 天` 生成，写 outbox（站内 + 邮件模板）
- [ ] 尾款支付成功后主单转「待发货」，进入正常发货流程
- [ ] 通知后 7 天未付 → 订单关闭，**定金不退**，状态流水记录原因
- [ ] 尾款金额 = 实付 - 定金，且与优惠分摊对齐（定金与尾款各自分摊，合计等于订单应付）

**涉及**：`POST /payments`（尾款）、定时任务、`ORDER_BALANCE_DUE` 邮件模板

## ISSUE-36 工期超时赔付

- 里程碑：M5 差异化
- 标签：`backend`, `settlement`, `p1`
- 依赖：#35
- 需求：ADR-0008

**背景**：超过承诺工期未发货，系统按天自动赔付。

**验收线**
- [ ] 定时任务扫「已过 `promised_ship_at` 且未发货」的子单，按天生成赔付（每天 5% 定金，上限 50%）
- [ ] 同一子单同一天只生成一条赔付记录（唯一索引兜底）
- [ ] 赔付金额进入结算扣减，商家结算单可见明细
- [ ] 赔付后若最终发货，赔付不撤回

**涉及**：新增 `penalties` 表、`PenaltyJob`

## ISSUE-37 售后单与审核

- 里程碑：M5 差异化
- 标签：`backend`, `refund`, `after-sales`, `p0`
- 依赖：#14, #20
- 需求：REQ-C-44（扩展）、ADR-0008

**背景**：把原来"整单退款"升级为独立售后单，支持仅退款与退货退款。

**验收线**
- [ ] 售后单独立编号，关联子单，记录类型、原因码、描述、证据图（≤3 张）
- [ ] 可申请窗口：子单完成后 15 天内；定制商品仅限「质量问题」「与描述不符」
- [ ] 商家 48 小时内审核；驳回必须填原因，顾客可补充证据后重新申请（限 1 次）
- [ ] 仅退款审核通过 → 直接退款；退货退款 → 进入待寄回

**涉及**：新增 `after_sales`/`after_sales_logs`、`POST /orders/{no}/sub-orders/{sub}/after-sales`

> 原 ISSUE-21（退款申请与商家审核）并入本 Issue，完成时关闭 #21。

## ISSUE-38 退货物流与质检入库

- 里程碑：M5 差异化
- 标签：`backend`, `merchant`, `after-sales`, `p0`
- 依赖：#37
- 需求：ADR-0008

**背景**：顾客寄回、商家收货、质检判定，决定是否退款与是否回补库存。

**验收线**
- [ ] 顾客填寄回物流（公司 + 单号），7 天未填 → 售后关闭
- [ ] 商家确认收货后 48 小时内提交质检：良品 / 残次，可附说明与图片
- [ ] 良品 → 回补库存并退款；残次 → 不回补库存，仍退款但计入商家责任率
- [ ] 质检超时未提交 → 系统按「良品」处理并自动退款（保护顾客）

**涉及**：`after_sales` 扩展字段、`POST /after-sales/{no}/return`、`/inspect`

## ISSUE-39 超时自动裁决与责任归属

- 里程碑：M5 差异化
- 标签：`backend`, `admin`, `after-sales`
- 依赖：#37, #38
- 需求：ADR-0008

**背景**：商家拖延是售后最常见的坑，系统要能自己往前走。

**验收线**
- [ ] 商家 48 小时不审核：仅退款自动通过；退货退款升级平台客服
- [ ] 责任归属三选一（商家 / 物流 / 顾客），决定退货运费谁承担
- [ ] 每次自动裁决写审计日志与状态流水，注明"SYSTEM"
- [ ] 客服可强制改判，需填原因

**涉及**：`AfterSalesTimeoutJob`、`PUT /admin/after-sales/{no}/verdict`

## ISSUE-40 售后与结算联动

- 里程碑：M5 差异化
- 标签：`backend`, `settlement`, `p1`
- 依赖：#24, #36, #38
- 需求：ADR-0008

**背景**：钱要算得清——售后冻结结算、退款冲抵、赔付扣减。

**验收线**
- [ ] 子单进入售后即冻结结算，关闭后解冻（未退款）或直接冲抵（已退款）
- [ ] 结算单增加 `refund_cent`、`penalty_cent`，公式：`应结 = 完成金额 - 退款 - 赔付`
- [ ] 对账任务校验：结算明细之和 = 子单实付 - 退款 - 赔付，差异告警
- [ ] 商家结算页能下钻到每一笔退款与赔付

**涉及**：`settlements` 新字段、`SettlementJob`、对账 SQL
