# 演示动线（V1.0.0 · 线上）

> 环境：`http://8.134.215.195`（HTTP，无 HTTPS）｜代码：`v1.0.0`（Flyway V24）｜口令统一 `Demo@123456`
> 文中标注「实测」的段落，是 2026-11-20 对线上真跑的 E2E 六场景（6/6 通过）；标注「未实测」的段落**演示前必须自己点一遍**。

## 一、演示前 5 分钟检查

```bash
# 1. 站点与接口活着（应当 8 项全 PASS）
BASE_URL=http://8.134.215.195 bash scripts/smoke.sh

# 2. 看邮件需要隧道（Mailpit 只在容器网络内，宿主机没映射端口）
ssh -fN -L 8026:$(ssh ecs "docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' kdshop-mailpit-1"):8025 ecs
#   → 浏览器开 http://127.0.0.1:8026

# 3. 浏览器用无痕窗口：避免上次演示的登录态/购物车干扰
```

同一台机器开三个窗口：顾客（无痕）、商家（无痕）、平台（无痕），各登录一个账号，演示时切窗口不切登录。

## 二、六段主线（全部实测）

| # | 讲什么 | 入口 | 操作 | 屏幕上看什么 |
|---|---|---|---|---|
| 1 | 注册与邮箱验证 | `/login` | 注册新邮箱 → 开 Mailpit 取验证链接 → 验证 → 登录 | `emailVerified=true`，账号页显示已验证 |
| 2 | 优惠券 | 平台 `/admin/coupons` → 顾客 `/coupons` | 平台建一张券 → 顾客在领券中心「领取」 | 券出现在「我的券」 |
| 3 | 加购 → 下单 → 支付 | 商品页 → `/cart` → `/checkout` | 加购 → 勾选 → 去结算 → 选地址与券 → 提交 → 模拟支付 | 订单变「已付款」，多商家自动拆单（每店一张子单） |
| 4 | 商家发货 | 商家 `/merchant/orders` | 找到子单 → 填运单号 → 发货 | 子单状态 `SHIPPED`，顾客侧同步 |
| 5 | 确认收货与评价 | 顾客 `/orders` | 确认收货 → 对订单项评分与写评论 | 按钮变「已评价」，商品详情页出现该评论 |
| 6 | 售后 | 顾客 `/after-sales` → 商家 `/merchant/after-sales` | 对已完成子单申请售后 → 商家同意退款 | 售后单 `REFUNDED`，生成退款记录 |

第 3 段是全场的重心：讲清**拆单**（一单多店 = 多子单、各自发货）、**库存与价格以服务端为准**、**支付回调幂等**。

## 四、翻车兜底

1. **站点打不开**：`ssh ecs 'cd ~/kdshop && docker compose ps'`；backend 不健康就 `docker compose restart backend`，等 40 秒。
2. **要回到上一版**：ECS `~/backup/` 里有 `app.jar.v16` + `web-v16.tgz` + `kdshop-post-v24.sql`（迁移后全库）。回滚 jar 后**数据库仍是 V24**（Flyway 不降级），只在「代码回退、数据不动」时用。
3. **完全没网/线上挂了**：本地 `scripts/dev.ps1 start` 一条命令起全栈，功能一致（地址 `http://localhost:5173`）。
4. **端口 8025 被本地占用**：上面隧道用 8026，别用 8025（本地 Mailpit 会抢）。

## 五、已知限制（主动说明，别等被问）

- 无 HTTPS：密码在公网明文传输，演示范围接受
- 邮件不真发：Mailpit 捕获，需要 SSH 隧道看
- 2 核 1.8G 跑 6 个容器：紧平衡，演示前不要同时开压测或大批量导图
