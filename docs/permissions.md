# 权限矩阵（G0）

六个角色、两套后台。商家只能看自己的店，平台角色看全量；功能权限与数据范围**两层都满足**才放行。

## 角色

| 角色 | 说明 |
|---|---|
| `GUEST` 游客 | 未登录，浏览、搜索、本地购物车 |
| `CUSTOMER` 顾客 | 下单、支付、查单、评价、收藏、申请入驻 |
| `MERCHANT` 商家 | 入驻审核通过后获得；管自己的商品、库存、订单、退款、结算 |
| `SUPPORT` 客服 | 平台侧售后：查订单、介入退款、看顾客（脱敏） |
| `OPERATOR` 运营 | 平台侧经营：类目、平台券、商家审核、全平台商品与订单 |
| `ADMIN` 管理员 | 角色分配、系统配置、审计、封禁 |

## 数据范围

| 资源 | 顾客 | 商家 | 客服 / 运营 / 管理员 |
|---|---|---|---|
| 主单 | 仅本人 | 含本店子单的主单（只见本店部分） | 全量 |
| 子单 | 无 | 仅本店 | 全量 |
| 退款 | 自己的 | 本店的 | 全量 |
| 商品 | 只看上架的 | 本店全部（含下架） | 全量 |
| 结算单 | 无 | 仅本店 | 全量 |
| 顾客资料 | 仅本人 | 仅订单收货信息（脱敏） | 脱敏后可见 |

## 关键规则

1. **`merchant_id` 只能由服务端从登录身份推导**，所有商家接口不接受前端传入的 merchant_id
2. 商家被封禁（`SUSPENDED`）后：商品立即下架、不能上新、不能登录商家后台；**已付款未发货的子单仍可发货**——否则伤的是顾客
3. 角色变更下一次请求即生效（会话里不缓存角色）
4. 前端菜单按角色渲染，只作体验，不作安全边界

## 验收线

1. 商家 A 请求商家 B 的子单详情 → 403
2. 商家访问 `/admin/*` 接口 → 403
3. 客服调用商品编辑接口 → 403；调用只读接口 → 200
4. 被驳回的入驻申请，用户再次提交后状态回到 `PENDING`
5. 管理员给用户加 `OPERATOR` 后，该用户下一请求即可进平台后台
