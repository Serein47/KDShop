# KDShop 需求与验收（G0）

> 每条需求 = ID + 一句话 + 可观测的验收线。验收线写法：Given 前置 / When 动作 / Then 结果。
> 优先级：P0 = 主线，不做就不算交付；P1 = 应当有；P2 = 有余力再做。
> 本文件只描述「做完是什么样」；实现状态由 PR 与 Issue 维护，不在这里打勾。

## 1. 角色

| 角色 | 说明 |
|---|---|
| 游客 | 未登录，可浏览、搜索、加购（本地暂存） |
| 顾客 | 已注册，可下单、支付、查单、评价、收藏、申请开店 |
| 商家 | 入驻审核通过后获得，管自己的店铺、商品、子单、退款、结算 |
| 客服 | 平台侧售后：查订单、介入退款、看顾客（脱敏）、看商家 |
| 运营 | 平台侧经营：类目、平台券、商家审核、全平台商品、结算生成 |
| 管理员 | 角色分配、佣金费率、系统配置、审计、封禁 |

## 2. 顾客端需求

### 2.1 账号与认证

| ID | 需求 | 优先级 | 验收线 |
|---|---|---|---|
| REQ-C-01 | 注册 | P0 | 未注册邮箱提交注册 → 建号成功并发出验证邮件（Mailpit 可见）；重复邮箱返回 409 且提示明确 |
| REQ-C-02 | 邮箱验证 | P0 | 点验证链接 → 账号置为已验证；过期或篡改的令牌 → 拒绝并提示重新发送 |
| REQ-C-03 | 登录 | P0 | 正确账密 → 建立会话并能访问「我的订单」；连续 5 次失败 → 该账号锁定 15 分钟 |
| REQ-C-04 | 登出 | P0 | 点登出 → 会话立即失效，回退后的页面不能再用旧会话请求 |
| REQ-C-05 | 找回密码 | P0 | 提交邮箱 → 发重置邮件；重置链接一次性、30 分钟过期；重置后旧会话失效 |
| REQ-C-06 | 修改资料与密码 | P1 | 改密码需验证旧密码；改完其他设备会话失效 |

### 2.2 商品浏览与搜索

| ID | 需求 | 优先级 | 验收线 |
|---|---|---|---|
| REQ-C-10 | 首页 | P0 | 展示轮播/分类入口/热销榜；首屏接口 p95 < 300ms（本地环境） |
| REQ-C-11 | 分类导航 | P0 | 两级分类可点；空分类显示空态而非报错 |
| REQ-C-12 | 商品列表 | P0 | 支持分页、价格区间、分类筛选、排序（销量/价格/上新）；刷新后筛选条件保持 |
| REQ-C-13 | 关键词搜索 | P0 | 搜「耳机」命中名称或描述含该词的已上架商品；无结果显示空态与推荐词 |
| REQ-C-14 | 商品详情 | P0 | 展示价格、库存、规格、图片、描述；已下架商品访问 → 404 提示 |

### 2.3 购物车

| ID | 需求 | 优先级 | 验收线 |
|---|---|---|---|
| REQ-C-20 | 加购 | P0 | 游客加购存本地，登录后合并到账号；超出库存 → 提示且不加入 |
| REQ-C-21 | 改数量/删除 | P0 | 数量为 0 视为删除；数量上限为库存；并发改同一行不产生负数 |
| REQ-C-22 | 合计 | P0 | 小计、优惠、运费、应付金额在服务端重算，前端金额仅用于展示 |

### 2.4 下单与支付

| ID | 需求 | 优先级 | 验收线 |
|---|---|---|---|
| REQ-C-30 | 收货地址 | P0 | 可新增/编辑/删除/设默认；下单时地址快照写入订单，后续改地址不影响历史订单 |
| REQ-C-31 | 提交订单 | P0 | 校验库存与价格 → 按商家拆成 1 个主单 + N 个子单 → 锁定库存、状态「待付款」；Σ子单金额 = 主单金额；同一购物车重复提交不生成两单 |
| REQ-C-32 | 订单超时取消 | P0 | 15 分钟未支付 → 自动取消并释放库存，状态与库存都可查 |
| REQ-C-33 | 模拟支付 | P0 | 跳转网关页 → 选成功/失败 → 回调验签通过才改单；重复回调只生效一次 |
| REQ-C-34 | 支付结果页 | P0 | 支付成功 → 订单转「已付款」并发邮件；支付失败 → 订单仍「待付款」可重试 |

### 2.5 订单

| ID | 需求 | 优先级 | 验收线 |
|---|---|---|---|

| REQ-C-41 | 订单详情 | P0 | 展示商品快照、金额明细、状态时间线 |

| REQ-C-44 | 申请退款 | P1 | 已付款/已发货的**子单**可提交整单退款，填写原因；进入「退款中」，由商家审核 |

## 3. 商家端需求

| ID | 需求 | 优先级 | 验收线 |
|---|---|---|---|
| REQ-M-01 | 商家登录 | P0 | 仅 `ACTIVE` 商家可登录；非商家提示「无店铺」，审核中提示「审核中」，封禁提示「已封禁」 |

| REQ-M-08 | 结算单 | P1 | 按周期查看应结、佣金、实结、明细；可导出 CSV |
| REQ-M-09 | 店铺看板 | P1 | 本店今日/近一周销售额、订单量、待发货数、热销 Top5 |
| REQ-M-10 | 数据隔离 | P0 | 访问他人店铺任意资源 → 403；前端传入 merchant_id 无效 |

## 5. 非功能需求

| ID | 需求 | 验收线 |
|---|---|---|
| REQ-N-01 | 一条命令起步 | 干净机器上 `docker compose up -d` + 后端/前端启动命令 → 可访问首页并登录种子账号 |
| REQ-N-02 | 响应式 | 375px 宽下首页、列表、详情、购物车、下单可完成 |
| REQ-N-03 | 可访问性 | 主流程可纯键盘完成；表单控件有标签；正文对比度 ≥ 4.5:1 |
| REQ-N-04 | 安全 | 密码 BCrypt 存储；接口鉴权；越权访问他人订单返回 403；SQL 注入与 XSS 基本防护 |
| REQ-N-05 | 观测 | 请求日志含 traceId；支付回调、下单失败有明确错误码 |
| REQ-N-06 | 可恢复 | 数据库每日备份脚本可执行，恢复步骤写进文档并在 G5 演练一次 |

## 6. 首版不做

多语言、多仓、商家券、平台补贴、部分退款、提现与打款对接、真实支付通道、真实邮件投递、智能购物伙伴（V2）、移动端 App、搜索引擎（ES）。
