# ADR-0007 模拟支付协议

- 状态：已接受
- 日期：2026-10-27

## 背景

不接真实支付通道，但支付是全项目最不能出错的一段。协议必须满足：防篡改、防重放、可幂等、可对账、将来能换成真实通道而不改业务代码。

## 决策

### 1. 报文签名用 HMAC-SHA256

参数按 key 字典序拼 `k=v&...`，末尾拼 `&key=secret`，取 HMAC-SHA256 小写十六进制。比较用常量时间函数。

不选非对称签名：模拟网关与平台同一信任域，对称密钥足够；真实通道各用各的（RSA2 / 证书），换的时候只替换 `PaymentChannel` 实现。

### 2. 三重防重放

| 手段 | 参数 | 作用 |
|---|---|---|
| 时间窗 | `timestamp` 偏差 < 5 分钟 | 拦截旧报文 |
| 随机串 | `nonce` 在 Redis 存 10 分钟 | 拦截同窗重放 |
| 业务幂等 | `outTradeNo` 唯一 + 状态条件更新 | 拦截重复入账 |

三者缺一不可：只有幂等键，攻击者仍可刷接口；只有时间窗，窗口内可重放。

### 3. 金额三方比对

回调金额必须同时等于：支付单金额、主单应付金额、网关侧交易金额。任一不等即拒绝并告警，不允许「以回调为准自动调整」。

### 4. 状态单向前进

`PENDING → SUCCESS / FAILED / CLOSED`，`SUCCESS → REFUNDED`。重复的 `SUCCESS` 回调直接返回成功，不重复扣库存、不重复发邮件。

### 5. 同步退款，但保留两态

模拟网关退款同步返回成功，平台仍按 `REFUNDING → REFUNDED` 两态记录。真实通道退款多为异步通知，这样换成真实通道时状态机不用改。

## 后果

- 密钥只存在环境变量 `PAY_GATEWAY_SECRET`，不落库、不落日志
- 需要每日对账任务：网关成功笔数/金额 vs 平台 `payments` 表
- 联调需要构造异常报文（错误签名、篡改金额、重放），这些场景写进 `05-支付网关.md` 的测试用例

## 何时重审

接入真实支付通道、需要分账（平台代收转商家）、或需要支持部分退款时。
