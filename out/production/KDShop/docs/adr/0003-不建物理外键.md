# ADR-0003 不建物理外键

- 状态：已接受
- 日期：2026-10-27

## 背景

关系型建模通常建议建外键保证引用完整性，但电商系统在写入路径上对锁与迁移敏感。

## 决策

不建物理外键，改用「逻辑外键 + 唯一索引 + 应用层校验」：

- 关联列一律建索引（如 `order_items.order_id`）
- 跨表一致性由 Service 层事务保证，删除一律软删
- 唯一性由数据库唯一索引兜底（`uk_orders_no`、`uk_payments_out_trade_no` 等）

## 后果

- 写入不触发外键检查，批量发货、批量改价更稳
- 数据质量靠测试与审计日志守住，需要定期跑一致性检查 SQL
- 未来分库分表时迁移成本更低

## 何时重审

如果团队规模扩大、出现多写入方，可以改为物理外键 + 逻辑删除的组合。
